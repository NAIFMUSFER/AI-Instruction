## Root cause and architectural changes

The fixtures declare `_provenance.kind = RECONSTRUCTED_TO_REPORTED_CENSUS` and `captured_from_live_backend = false`. They preserve a historical element census, not a validated design. Neither original fixture is changed in this patch.

Two concrete contradictions under the existing room-host contract are:

1. `typical_storage_00` contains a rack with `h: 8.5`, `levels: 4`, while the model's host wall height is `3.8`. The second raised deck has a lower world bound of approximately `4.235`, giving a vertical separation of **0.435 m** above that host. The old distance formula only considered x/z, explaining its false zero.
2. `typical_picking_01` begins at x = `12.2`, has width `11`, and contains a desk with room-local x = `13.4`. The existing compiler applies the room origin once, placing that coordinate at x = `25.6`, beyond the host's x maximum `23.2`. Inferring a different coordinate frame would silently reinterpret the supplied data.

Real Three.js geometry and independently inspected world boxes give the same diagnostic census for each fixture: **1,378 checked; 406 INSIDE; 360 INTERSECTING_BOUNDARY; 612 OUTSIDE; 0 UNRESOLVED**. Outside objects have separating gaps on x/y/z for **306/270/280** meshes respectively; those axis counts overlap and must not be summed as an object total.

The bridge now measures `max(dx, dy, dz)`, reports the separating axes, and exposes `REVIEW_REQUIRED` when hosted objects are outside/unresolved or elements are detached. An otherwise clear report uses `NOT_EVALUATED`, never an engineering-approval status. This remains a read-only rendering diagnostic, not regulatory validation.

The test expectation is explicit and scoped to SHA-256 fingerprints of the two parsed fixture models (`JSON.stringify` serialization). It requires the complete containment census, axis counts, review status, no model writes and no objects moved to fit. A changed fixture, added conflict, hidden conflict, lost vertical count, downgraded review status or moved object fails. Other browser fixtures retain the zero-outside assertion. Existing transform, plate, roof, pixel, resize and model-invariance checks remain in place.
