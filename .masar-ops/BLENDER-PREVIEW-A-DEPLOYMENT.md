## Accepted option A, not cloud rendering
Open the website, choose **إخراج Blender**, select a finish, and press **معاينة بالخامات**. The optional Three.js WebGL2 viewer is built and hosted on this same origin. Users can rotate the model, hide the roof, and select rooms linked to the MASAR plan. The existing 2D/basic-3D editor remains available.

Three finishes are available: **حجر فاتح وخشب دافئ**, **أبيض مع أرضية فاتحة**, **حجر رمادي وخشب**. The panel exports **MASAR-Blender-Scene.json** for the trusted local Blender script; this JSON is not a native .blend file. Finish, camera-room, furniture and image-resolution choices are exported without changing canonical project history.

`BLENDER_RENDER_ENABLED=false`. Live capability endpoint confirms `enabled=false`, `workerOnline=false`, pipeline `blender-bridge-1.0.0`. The cloud-render button is disabled and explains why. Even an authenticated API request receives 503 and creates no render job. There is no hosted Blender worker, paid GPU, or permanent render output storage. No new .blend, GLB or Cycles images for a user's project are generated by this public preview. Previously generated CI sample outputs are examples only, not the user's current model.

## Boundaries and operations
The account SQLite database is `/tmp/masar-blender-preview/masar.sqlite`, with `PERSISTENCE_CLASS=ephemeral`. Save important projects as exported MASAR JSON on the user's device; server data can disappear on restart/redeploy/spindown. The enhanced WebGL2 view is separate from Cycles rendering. Images/resolution controls configure local scene export; they are not a promise of cloud rendering. External AI is not configured. Browser testing used software-accelerated Chromium, not physical iPhone hardware. Render plan Free has shared usage quotas; it is not an unlimited-cost guarantee. No paid compute subscription was created.
